# Заметки по использованию ADXL345 для балансировки

Эти заметки описывают сценарий, где ADXL345 закреплен на неподвижной раме,
корпусе или основании, а не на самой вращающейся детали. Это более безопасная и
практичная схема: вращающийся элемент создает вибрацию, а датчик измеряет, как
эта вибрация передается на неподвижную конструкцию.

## Что сейчас измеряет код

Текущий скетч для ESP32-C3 читает ускорение по оси X и хранит исторический
максимум в `xMax`.

Это подходит для простого сценария "поймать худшую вибрацию за прогон":

1. Включить устройство.
2. Раскрутить вращающийся элемент.
3. Посмотреть максимальное значение.
4. Остановить, изменить балансировочный грузик, перезапустить или сбросить
   измерение и сравнить результат.

В таком сценарии текущая логика имеет смысл. Чем выше `Max`, тем более сильный
пик по оси X увидел датчик за этот прогон.

## Главное ограничение

`xMax` - это исторический максимум с момента включения. Он не показывает текущий
уровень вибрации.

После одного сильного случайного пика светодиод снова сработает только если
следующее измерение превысит старый пик на `TRIGGER_STEP`. Параметр
`RESET_DROP` разрешает следующую проверку пика, но не уменьшает сам `xMax`.

Это нормально, если цель - сохранить максимальное значение за тестовый прогон.
Но это хуже подходит, если нужно видеть, стало ли лучше или хуже прямо сейчас.

## Более полезные метрики для балансировки

Для балансировки обычно полезнее измерять вибрацию в коротком временном окне, а
не хранить только максимум за все время работы.

Хорошие варианты:

- `peak-to-peak`: максимум минус минимум ускорения за последние 1-3 секунды.
- `RMS`: среднеквадратичное значение ускорения за последние 1-3 секунды.
- Отдельные значения по осям X, Y и Z.
- Модуль вектора: `sqrt(x*x + y*y + z*z)`, чтобы результат меньше зависел от
  ориентации датчика.

Для первого практического варианта `peak-to-peak` за фиксированное окно часто
самый понятный показатель: меньше значение - меньше вибрация.

## Рекомендуемый алгоритм

Для этого проекта лучше начать не со сложного частотного анализа, а с простой
оценки вибрации в окне. Такой алгоритм проще написать, объяснить и сравнивать
между попытками балансировки.

Рекомендуемый первый вариант:

1. Читать ADXL345 с фиксированной частотой, например 100 Гц.
2. Для каждого измерения считать либо вибрацию только по X, либо модуль вектора.
3. Хранить измерения за короткое окно, например 1 секунду.
4. Для этого окна считать `min`, `max` и `peak-to-peak = max - min`.
5. Показывать текущий `peak-to-peak` и лучший/худший результат за текущий
   прогон.
6. Добавить ручной сброс перед каждой попыткой балансировки.

Тогда рабочий процесс будет понятным:

1. Закрепить датчик на неподвижной раме.
2. Каждый раз запускать мотор на одинаковых оборотах.
3. Дождаться стабилизации показаний.
4. Записать значение вибрации за окно.
5. Переместить или изменить балансировочный грузик.
6. Сбросить измерение и повторить.
7. Выбрать вариант с самым низким стабильным значением вибрации.

### Ось X или модуль вектора

Использовать только X нормально, если датчик всегда закреплен одинаково и
основная вибрация действительно идет примерно вдоль этой оси.

Для более универсального варианта лучше считать модуль вектора:

```cpp
float magnitude = sqrt(x * x + y * y + z * z);
```

Но сырой модуль включает гравитацию. Для балансировки обычно полезнее убрать
медленную или статическую составляющую. Простой практичный вариант - вести
медленное скользящее среднее и смотреть отклонение от него:

```cpp
baseline = baseline * 0.98f + magnitude * 0.02f;
vibration = abs(magnitude - baseline);
```

После этого уже можно считать `peak-to-peak` или RMS по `vibration` за окно
измерения.

### Peak-to-peak или RMS

`peak-to-peak` проще понять и удобно использовать для ранних экспериментов. Он
сильно реагирует на случайные удары, касание рамы или переходные процессы.

`RMS` обычно лучше отражает общую "энергию" вибрации:

```cpp
rms = sqrt(sum(vibration * vibration) / sampleCount);
```

Практичный экран может показывать сразу несколько значений:

- `Now`: RMS или peak-to-peak за текущее окно в 1 секунду.
- `Best`: минимальное стабильное значение после сброса.
- `Max`: максимальный пик после сброса.

### Стабилизация оборотов

Не стоит сравнивать значения, пока мотор еще раскручивается. Лучше начинать
измерение после небольшой задержки или добавить кнопку/Serial-команду, которая
запускает тест, когда обороты уже стабильны.

Если обороты между попытками разные, значения вибрации могут быть несравнимыми.
Для ручной балансировки лучше каждый раз запускать механизм на одинаковой
скорости.

### Поведение светодиода

Если цель именно балансировка, светодиоду не обязательно мигать только при новом
историческом максимуме по X. Более полезные варианты:

- Мигать, если текущая вибрация в окне выше заданного порога.
- Светить ярче при росте вибрации.
- Мигать, когда найден новый лучший, то есть более низкий, уровень вибрации.

Для балансировки обратная связь "стало лучше" часто полезнее, чем "пойман новый
максимум вибрации".

## Что улучшить дальше

- Добавить сброс `xMax`, например кнопкой, командой в Serial или автоматически
  при старте нового теста.
- Показывать текущую вибрацию за окно вместе с историческим максимумом.
- Отслеживать хотя бы X и Y или использовать модуль вектора, чтобы ориентация
  датчика меньше влияла на результат.
- Если известна скорость вращения, в следующих версиях можно анализировать
  вибрацию за один оборот или перейти к частотному анализу.

## Практическая интерпретация

Для быстрых экспериментов текущий код достаточно хорошо отвечает на вопрос:

"В этом прогоне был пик сильнее, чем в предыдущем?"

Для полноценной балансировки лучше двигаться к вопросу:

"Насколько сильная вибрация прямо сейчас, если измерять ее за последние несколько
секунд?"
